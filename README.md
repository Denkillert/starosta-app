# Староста — помощник старосты группы ПолесГУ

Неофициальное приложение для старосты: расписание с `polessu.by/ruz`, журнал
посещаемости, распоряжения, заявления и справки. Веб-интерфейс
сделан как мобильный Telegram Mini App, плюс есть небольшой бот на aiogram.

Проект некоммерческий: без подписок, рекламы и платёжных функций.
Юридическую силу имеют только документы вуза, а не это приложение.

## Что уже работает

- **Импорт расписания** группы с сайта ПолесГУ по номеру (`24ИТ-2`) для 1 и 2 семестра.
- **Сохранение истории**: шаблоны пар (`lessons`) и конкретные даты (`lesson_occurrences`)
  разделены, поэтому пересинхронизация не стирает старые отметки.
- **Расписание без ручных отмен**: если пары нет на сайте вуза, её нет и в
  приложении. К паре можно добавить заметку — её видят все студенты группы.
- **Журнал как в ведомости**: строки — студенты в алфавитном порядке (должность
  не влияет), столбцы — пары дня с предметом, временем и счётчиком
  «присутствуют/всего». По умолчанию все присутствуют (зелёная галочка),
  отмечаются только отсутствующие («Н»). Староста отмечает всю пару локально,
  без перезагрузки страницы, и отправляет всё одной кнопкой «Подтвердить» —
  сервер сохраняет пачку отметок одной транзакцией. «У» ставится документом,
  «опоздал / не ответил» убраны.
- **Фирменное оформление ПолесГУ**: тёмно-зелёный `#054226`, мятный
  `#e3f3f0` и зелёный акцент в светлой и тёмной темах Mini App.
- **Документы**: Единая сущность `Document` с тремя типами: `order`
  (распоряжение — освобождение от занятий), `statement` (заявление),
  `certificate` (справка). У распоряжения обязательны номер, дата и период
  действия с точностью до времени. Одно распоряжение может освобождать
  нескольких студентов.
- **Автоматическая «уважительная»**: активное распоряжение или
  справка ставит `excused` только на пары, которые пересекаются с периодом
  действия; при отзыве/удалении отметки снимаются.
- **Ведомости за месяц в .docx**: «Ведомость учета учебных часов, пропущенных
  студентами» (студенты × дни, часы, ИТОГО, по уваж./безуваж., списки справок,
  заявлений и распоряжений, часы отработки по дисциплинам) и «Ведомость учета
  платных отработок по дисциплине» (отдельная таблица на предмет и преподавателя,
  18,47 BYN за пару, ЕРИП, дата оплаты, подпись). Бланки повторяют образцы вуза:
  37/13 колонок, объединённые ячейки шапки и места для подписей.
- **Подгруппы**: у студента можно указать подгруппу 1 или 2. Лабораторные пары
  в расписании помечены «1 группа» / «2 группа», поэтому пропуск по чужой
  подгруппе не ставится и не попадает в журнал, статистику и ведомости.
- **Заявки по коду приглашения**: новый участник создаётся как заявка, староста
  и заместитель получают сообщение в Telegram. На странице «Студенты» можно
  подтвердить ФИО и подгруппу или привязать Telegram к уже заведённому студенту.
- **Статистика** по студентам и предметам, выгрузка CSV для Excel.
- **Студенты группы**: староста и заместитель добавляют студентов по ФИО (Telegram
  не обязателен), переименовывают, меняют роль, форму обучения, подгруппу и статус
  «учится / отчислен». Дубли ФИО в одной группе не допускаются.
- **Скачивание ведомостей на телефоне**: `.docx` открываются в системном браузере
  по подписанной ссылке (внутри Telegram WebView файлы не сохраняются), поэтому
  cookie Mini App не нужен.
- **Своя база на каждую группу**: `data/groups/<код>.db` — отдельный SQLite-файл
  только с данными этой группы (студенты, пары, посещаемость, документы, журнал
  действий). Пересобирается при скачивании со страницы «Студенты».
- **Фоновая синхронизация**: веб-процесс сам проверяет расписание каждые
  несколько часов и обновляет только устаревшие семестры, с паузой между
  запросами к сайту вуза. Состояние видно на странице «Отчёты» и в
  `GET /api/scheduler`.
- **Telegram-авторизация**: подписанный `initData` обменивается на cookie-сессию;
  в dev-режиме можно ходить с заголовком `X-Telegram-Id`.
- **Демо-группа 24ИТ-2** с офлайн-фикстурами: можно посмотреть всё без сети.

## Заглушки (осознанно не реализовано)

- **Опросы** — отложены.
- **Оплата отработок** — в ведомости есть колонки ЕРИП/дата оплаты, но сами
  платежи не проводятся: их заполняют вручную или в вузе.

## Быстрый старт (Windows PowerShell)

```powershell
cd starosta-app
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -r requirements-dev.txt
Copy-Item .env.example .env          # если файла .env ещё нет
.\.venv\Scripts\python.exe -m app.cli seed
.\.venv\Scripts\python.exe -m app.cli serve
```

### Запуск одной кнопкой: `start.bat`

`start.bat` поднимает всё сразу: веб-сервер на `0.0.0.0:8000` (доступен и с
телефона в Wi-Fi), HTTPS-туннель `cloudflared` и бота. Скрипт сам дожидается
адреса туннеля, записывает его в `WEB_BASE_URL` и только потом запускает бота;
бот при старте обновляет кнопку меню в Telegram, поэтому копировать ссылку
вручную не нужно. Повторный запуск закрывает предыдущие процессы.

Каждый запуск cloudflared выдаёт новый адрес `https://...trycloudflare.com`,
поэтому кнопка меню обновляется автоматически. Окна сервера, бота и туннеля
можно закрыть — сторож поднимет их заново (уже без окон, с логами в `%TEMP%`).
Полностью остановить всё: `stop.bat`.

**Бесплатный домен может смениться сам.** У localhost.run домен периодически
заменяется (в `%TEMP%\ssh-tunnel.log` видно `tunnel ... removed` и новый
адрес): `ssh.exe` при этом жив, а старая ссылка `https://....app.lhr.life`
уже не открывается. Поэтому `start.bat` запускает сторожа
`tools/tunnel-watch.ps1` — он раз в 20 секунд проверяет сервер, бота и
туннель, при смене домена переписывает `WEB_BASE_URL` в `.env` и обновляет
кнопку меню (`python -m tools.update_menu`), а упавшие процессы поднимает
заново. Работающие сервер и бот перечитывают `.env` сами, перезапускать их
не нужно. Лог сторожа: `%TEMP%\starosta-watch.log`.

#### Если туннель не поднимается на мобильном интернете

Симптом: окно `cloudflared` пишет
`failed to request quick Tunnel ... tls: failed to verify certificate: x509:
certificate has expired or is not yet valid`.

Это не ошибка приложения. Мобильные операторы (в Беларуси — `life:`,
`A1`, `МТС`) подменяют DNS для `*.trycloudflare.com` и отдают адрес своего
сервера с чужим сертификатом. Диагностика на проблемной сети:

```powershell
Resolve-DnsName api.trycloudflare.com -Type A     # 10.x.x.x вместо 104.16.x.x
curl.exe -sS -o NUL https://api.trycloudflare.com/tunnel   # SEC_E_CERT_EXPIRED
```

`start.bat` обходит это сам: если cloudflared не выдал адрес за ~20 секунд,
скрипт запускает SSH-туннель через `localhost.run` (порт 22/443, без
регистрации и без установки — используется встроенный в Windows `ssh.exe`).
Адрес получается вида `https://xxxx.app.lhr.life`, он так же записывается в
`.env`, и бот обновляет кнопку меню. Ничего скачивать и менять DNS не нужно.

Принудительный выбор: `set TUNNEL_PROVIDER=ssh` или
`set TUNNEL_PROVIDER=cloudflare` перед запуском `start.bat`. Полный лог
запуска пишется в `%TEMP%\starosta-start.log`.

Оговорки: quick tunnel и localhost.run — бесплатные временные туннели.
Адрес меняется при каждом запуске (и периодически сам у localhost.run);
сторож переносит новый адрес в `.env` автоматически. Для постоянного адреса:
зарегистрируйтесь на `admin.localhost.run` и добавьте SSH-ключ — бесплатные
домены живут дольше; либо подключите свой домен (Custom Domain plan), либо
используйте именованный туннель Cloudflare или VPS — тогда ссылка не меняется
и не зависит от политики оператора.

`serve` слушает `0.0.0.0:8000` и печатает два адреса: локальный
`http://127.0.0.1:8000` и сетевой `http://192.168.x.x:8000`. Второй открывается
с телефона, если он в той же Wi-Fi. Если браузер телефона не подключается,
разрешите порт в брандмауэре Windows от имени администратора:

```powershell
New-NetFirewallRule -DisplayName "Starosta 8000" -Direction Inbound -LocalPort 8000 -Protocol TCP -Action Allow
```

Порт и адрес можно изменить: `-m app.cli serve --host 127.0.0.1 --port 8080`
или переменными `HOST` / `PORT` в `.env`. Для разработки с автоперезагрузкой
добавьте `--reload`.

Если сервер уже запущен в другом окне, `serve` не падает с `WinError 10048`,
а пишет, что приложение уже работает, и показывает адреса. Остановить его:

```powershell
.\.venv\Scripts\python.exe -m app.cli stop
```

`stop` завершает только Python-процесс, который слушает порт, поэтому чужие
программы не затрагиваются.

Откройте <http://127.0.0.1:8000>. По умолчанию используется SQLite
`data/starosta.db`, пользователь-разработчик задаётся `DEV_TELEGRAM_ID`.

Второй терминал — бот (после того как вписан токен):

```powershell
cd starosta-app
.\.venv\Scripts\python.exe -m bot.main
```

Linux/macOS:

```bash
cd starosta-app
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt -r requirements-dev.txt
cp .env.example .env
.venv/bin/python -m app.cli seed
```

### Демо-данные

```powershell
.\.venv\Scripts\python.exe -m app.cli seed            # офлайн-фикстуры 24ИТ-2
.\.venv\Scripts\python.exe -m app.cli seed --live    # затем живой запрос на polessu.by
```

`seed` идемпотентен: повторный запуск не дублирует группу, а при необходимости
привязывает текущего dev-пользователя к существующей демо-группе.

## Настройки (.env)

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///./data/starosta.db` | SQLite или MySQL 8 |
| `BOT_TOKEN` | пусто | токен @BotFather; без него бот не стартует |
| `BOT_USERNAME` | пусто | имя бота без `@`, для подсказок |
| `WEB_BASE_URL` | `http://localhost:8000` | адрес приложения для кнопки в боте; `localhost` заменяется на IP в Wi-Fi, публичный HTTPS включает Mini App |
| `SESSION_SECRET` | пусто | секрет cookie-сессии; если пуст — берётся `BOT_TOKEN` |
| `DEV_MODE` | `true` | `true`: гостевой вход по `X-Telegram-Id`/`DEV_TELEGRAM_ID`, но только при прямом подключении (LAN): запрос не должен приходить с прокси-заголовками или с публичного домена в `Host`. Через туннель всегда требуется Telegram `initData` |
| `DEV_MODE_PUBLIC` | `false` | `true` разрешает гостевой вход и через туннель (небезопасно: ссылку откроет любой) |
| `DEV_TELEGRAM_ID` | `100000001` | пользователь dev-режима |
| `DEV_USER_NAME` | `Староста` | ФИО dev-пользователя |
| `UPLOAD_DIR` | `./data/uploads` | приватные файлы документов |
| `MAX_UPLOAD_MB` | `10` | лимит файла |
| `TIMEZONE` | `Europe/Minsk` | локальное время и даты |
| `HOST` | `0.0.0.0` | адрес веб-сервера; `0.0.0.0` — доступ из локальной сети |
| `PORT` | `8000` | порт веб-сервера |
| `ACADEMIC_HOURS_PER_LESSON` | `2` | учебных часов в одной паре |
| `PAID_LESSON_RATE` | `18.47` | стоимость платной отработки за пару, BYN |
| `SCHEDULE_SYNC_HOURS` | `6` | через сколько часов расписание считается устаревшим |
| `SCHEDULER_ENABLED` | `true` | фоновая синхронизация в веб-процессе |
| `SCHEDULER_STARTUP_DELAY_SECONDS` | `60` | пауза перед первым проходом после старта |
| `SCHEDULER_INTERVAL_MINUTES` | `0` | период проверки; `0` — `SCHEDULE_SYNC_HOURS * 60` |
| `POLESSU_CRAWL_DELAY_SECONDS` | `10` | пауза между запросами к polessu.by |

Для продакшена:

```dotenv
DEV_MODE=false
BOT_TOKEN=123456:...
WEB_BASE_URL=https://ваш-домен.example
SESSION_SECRET=длинная-случайная-строка
```

`DEV_MODE=false` включает `Secure` у cookie, поэтому нужен HTTPS. Внутри
Telegram страница сама отправляет `initData` на `POST /auth/telegram` и получает
cookie; после этого обычные ссылки работают без заголовков.

## MySQL (необязательно)

По умолчанию проект работает на SQLite. Для MySQL 8 создайте базу и укажите
строку подключения в `.env`:

```dotenv
DATABASE_URL=mysql+pymysql://starosta:starosta@127.0.0.1:3306/starosta?charset=utf8mb4
```

Схема создаётся автоматически при старте (`init_db()`), недостающие колонки
добавляются совместимыми `ALTER TABLE`. Alembic/миграций пока нет — для
изменения схемы в разработке проще пересоздать локальную БД. Готовых
Docker-файлов в проекте нет: MySQL и приложение запускаются вручную.

### Файл базы на каждую группу

Рабочая база (`DATABASE_URL`) остаётся общей — так проще авторизация и переходы
между группами. Дополнительно приложение умеет собирать автономный файл одной
группы:

```
data/groups/<код группы>.db
```

В нём только строки этой группы: `groups`, `memberships`, `lessons`,
`lesson_occurrences`, `attendance`, `documents`, `document_students`,
`schedule_snapshots`, `audit_log`, плюс связанные `subjects` и `users`.
Скачивание — на странице «Студенты», кнопка «Скачать базу группы (.db)»
(доступно старосте и заместителю). Файл пересобирается при каждом скачивании,
поэтому всегда актуален; ссылка подписана и работает без cookie.

```powershell
# посмотреть файлы групп
Get-ChildItem data\groups
```

## Бот

1. Создайте бота у @BotFather (`/newbot`) и скопируйте токен вида
   `123456789:AAH...`.
2. Откройте файл **`starosta-app/.env`** и впишите токен в строку `BOT_TOKEN=`
   (в текущем `.env` это строка 11):

   ```dotenv
   BOT_TOKEN=123456789:AAH...
   BOT_USERNAME=имя_вашего_бота
   ```

   `BOT_USERNAME` — имя без `@`; оно нужно для ссылок `t.me/...?start=КОД`.
3. `WEB_BASE_URL` можно оставить `http://localhost:8000` — бот сам подставит
   IP компьютера в Wi-Fi и покажет кнопку «Открыть в браузере». Такой адрес
   открывается с телефона в той же сети, но Mini App-режим (внутри Telegram,
   на весь экран) требует публичного HTTPS-адреса. Проще всего запустить
   `start.bat`: он поднимет туннель и сам впишет его адрес в `WEB_BASE_URL`,
   после чего кнопка станет «Открыть приложение».

   Если провайдер блокирует `trycloudflare.com` (DNS возвращает чужой IP и
   TLS-ошибку), используйте другой туннель — `ngrok http 8000`,
   `ssh -R 80:localhost:8000 nokey@localhost.run` — и впишите его
   `https://`-адрес в `WEB_BASE_URL` вручную.
4. Запустите бота в отдельном терминале:

```powershell
cd starosta-app
.\.venv\Scripts\python.exe -m bot.main
```

Без токена команда не падает, а печатает, куда его вставить.

Команды:

| Команда | Что делает |
| --- | --- |
| `/start` | приветствие; `t.me/bot?start=КОД` сразу присоединяет к группе |
| `/app` | ссылка на приложение (или кнопка Mini App, если настроен HTTPS) |
| `/today`, `/tomorrow` | пары на сегодня / завтра |
| `/week` | расписание на текущую неделю |
| `/journal` | сводка посещаемости за сегодня |
| `/stats` | посещаемость за месяц и студенты ниже 75% |
| `/documents` | последние документы |
| `/invite` | код приглашения и ссылка (староста/зам) |
| `/sync` | обновить расписание с сайта вуза (староста/зам) |
| `/help` | краткая инструкция |

Любое сообщение с кодом приглашения (например, `79S53H`) присоединяет
пользователя к группе. Бот использует ту же БД, что и веб-приложение,
поэтому запускайте его из каталога `starosta-app`.

## Ведомости и документы

На странице **«Отчёты»** выберите месяц и скачайте одну из форм:

| Форма | Что внутри | Файл |
| --- | --- | --- |
| Ведомость учета учебных часов, пропущенных студентами | студенты × дни месяца, часы за пары, ИТОГО, по уваж./безуваж., списки справок, заявлений и распоряжений, часы отработки по дисциплинам | `/reports/propuski.docx?month=2026-10` |
| Ведомость учета платных отработок по дисциплине | отдельная таблица на каждый предмет и преподавателя: дата пропуска, 18,47 BYN, ЕРИП, дата оплаты, подпись | `/reports/paid.docx?month=2026-10` |

Оба файла печатаются не «по мотивам», а прямо по бланку университета. Бланки
лежат в `app/resources/docx` (`propuski.docx`, `paid.docx`) и собраны из
настоящих образцов скриптом `tools/build_docx_templates.py`: из образцов
убраны фамилии и отметки, вместо них подстановки `{{MONTH}}`, `{{GROUP}}` и т.п.
Поэтому шрифты (Arial 7 / Calibri 10 в ведомости пропусков, Times New Roman
12–14 в платных отработках), размеры колонок, объединения ячеек, высоты строк,
поля страницы и разрывы страниц совпадают с бланком один в один.

Когда бланк в вузе меняется, положите новый `.docx` в `D:\Универ` и пересоберите
шаблоны:

```powershell
.\.venv\Scripts\python.exe tools\build_docx_templates.py
```

Логика отметок:

- В журнале отмечают **только отсутствующих**: зелёная галочка — студент был,
  «Н» — пропуск. Клетку с «У» вручную переключить нельзя.
- Отметки на странице копятся локально: страница не перезагружается после
  каждого нажатия. Когда староста отметил всех, он нажимает «Подтвердить» —
  все изменения уходят на сервер **одним запросом**. Если сервер отклонил
  хотя бы одну строку, не сохраняется ничего, а несохранённые клетки
  подсвечиваются пунктиром.
- «Н» — неуважительный пропуск. «У» нельзя поставить руками: она появляется,
  если на пару действует активное распоряжение или справка.
- В конце месяца «Н» можно оставить как есть или оформить документ — тогда
  часы перейдут в «По уваж.». Опоздания и «не ответил» не используются.
- У распоряжения обязательны **номер**, **дата** и **период действия**; время
  начала и окончания необязательно (пусто = весь день). Одно распоряжение может
  освобождать несколько студентов.
- Заметка к паре видна всей группе, но не отменяет пару. Если пары нет на сайте
  вуза, она просто не появляется в расписании.

## Фоновая синхронизация

Планировщик живёт внутри веб-процесса (`uvicorn`), отдельный воркер не нужен.
После старта он ждёт `SCHEDULER_STARTUP_DELAY_SECONDS`, затем раз в
`SCHEDULER_INTERVAL_MINUTES` (по умолчанию — раз в `SCHEDULE_SYNC_HOURS` часов)
проверяет, у каких групп расписание старше порога, и обновляет только их.
Между запросами к `polessu.by` выдерживается `POLESSU_CRAWL_DELAY_SECONDS`.

- Если содержимое не изменилось, синхронизация возвращает `unchanged` и
  ничего не пишет в базу.
- Если пара исчезла из расписания, она пропадает из журнала; уже выставленные
  отметки не удаляются из базы, чтобы история месяца не ломалась.
- Отметки посещаемости и заметки к парам сохраняются.
- Состояние последнего прохода: страница «Отчёты» и `GET /api/scheduler`.
- Бот планировщик не запускает; `/sync` в боте — разовое обновление.
- Отключить: `SCHEDULER_ENABLED=false` в `.env`.
- Разовый проход из CLI (например, для cron):

```powershell
.\.venv\Scripts\python.exe -m app.cli sync-all --hours 6
.\.venv\Scripts\python.exe -m app.cli sync-all --force --term 1 --delay 15
```

## Импорт расписания

Источник: `https://www.polessu.by/ruz/?f=<семестр>&q=<группа>`.

- `f=1` — первый семестр, `f=2` — второй (метки кнопок на сайте могут не совпадать).
- Парсер ищет `tbody#weeks-filter`, дни `tr.wa`, пары `tr.wN` (неделя `N+1`).
- Дисциплина и вид пары разбираются из ячейки вида `(2, 14) Предмет - лек.`.
- Изменения на сайте определяются по SHA-256 содержимого; при совпадении
  синхронизация возвращает `unchanged` и ничего не пишет.
- Если пара исчезла из расписания, но на ней уже есть отметки, запись помечается
  отменённой и скрывается из интерфейса; история посещаемости сохраняется.
- Уважайте `Crawl-delay: 10` из `robots.txt`: не синхронизируйте чаще, чем
  раз в несколько часов, и не делайте параллельных запросов по всем группам.

Фикстуры для офлайн-тестов лежат в `tests/fixtures/` и `app/fixtures/`.
Живой HTML не коммитится в демо-архив без необходимости.

## API

Все эндпоинты, кроме `/api/health`, требуют авторизацию: cookie-сессию,
`X-Telegram-Init-Data` или (в dev-режиме) `X-Telegram-Id`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/health` | проверка живости |
| GET | `/api/me` | пользователь и его группы |
| POST | `/api/groups` | создать группу |
| POST | `/api/groups/join` | присоединиться по коду |
| GET | `/api/groups/{id}` | группа и участники |
| GET/POST | `/api/groups/{id}/members` | список / добавить студента |
| PATCH | `/api/groups/{id}/members/{member_id}` | роль, статус, ФИО |
| POST | `/api/groups/{id}/sync?term=1` | синхронизировать расписание |
| GET | `/api/groups/{id}/schedule?date=&days=` | расписание на диапазон |
| GET | `/api/groups/{id}/journal?date=` | журнал на день |
| POST | `/api/occurrences/{id}/attendance` | массовые отметки |
| GET | `/api/groups/{id}/stats?from=&to=` | статистика |
| GET/POST | `/api/groups/{id}/documents` | список / создать документ |
| GET/PATCH/DELETE | `/api/documents/{id}` | документ |
| POST | `/api/documents/{id}/status` | сменить статус |
| GET | `/api/documents/{id}/file` | скачать файл |
| GET | `/api/reports` | список отчётов |
| POST | `/api/reports/{kind}` | `501` — заглушка |
| GET | `/api/ai/status` | ИИ выключен |
| GET | `/api/scheduler` | состояние фоновой синхронизации |

Интерактивная документация: `/docs`, OpenAPI: `/openapi.json`.

## Ограничения и важные оговорки

- Приложение **неофициальное** и не связано с ПолесГУ. При расхождении данных
  приоритет всегда у сайта вуза и документов деканата.
- Документы в приложении — это учёт, а не бланки с подписями. Справки,
  заявления и распоряжения не имеют юридической силы без вуза.
- Медицинские подробности не хранятся: у справки только период и основание.
- Файлы доступны только участникам группы с соответствующими правами и лежат
  вне публичного каталога.
- Персональные данные студентов вносятся вручную; не загружайте лишнее
  (паспорта, диагнозы, номера телефонов), если без этого можно обойтись.
- Расписание может измениться на сайте в любой момент — обновляйте его перед
  важными днями.
- В репозитории нет продакшен-миграций, резервного копирования и мониторинга;
  для реальной эксплуатации их нужно добавить отдельно.
- Не используйте приложение для слежки за студентами. Посещаемость — учебный
  учёт, а не инструмент контроля.
